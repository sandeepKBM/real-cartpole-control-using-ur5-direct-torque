# Hardware-lane (real UR5e / hardware/ + tools/ur5e_*.py) Python dependencies.
#
# This is separate from environment.yml (the conda env for simulation/RL work)
# because the hardware lane runs on real robot-adjacent machines (e.g. the
# ROS2 Humble host next to the arm) that are set up with a plain venv, not
# conda -- see docs/hardware/HARDWARE_GUIDE.md.
#
# Written 2026-07-30 after a live lab session where two dependencies each
# individually satisfied this project's previously-documented version floor
# but were STILL missing the specific attribute the code actually calls,
# discovered only by crashing on real hardware mid-session:
#   - ur_rtde 1.6.1 (satisfies ">=1.6", the old documented floor) has no
#     RTDEControlInterface.directTorque -- direct_torque mode cannot connect
#     at all with this build.
#   - a pip-installed pinocchio satisfying ">=3.1" had no
#     pin.buildModelFromMJCF -- crashed the (now gracefully-degrading)
#     diagnostic residual observer, and would also break
#     dynamics_source=local_pinocchio / gravity_source=pinocchio.
#
# LESSON, baked into the version floors below where confirmed, and into a
# real verification step where not: a version number satisfying a ">="
# floor does NOT guarantee the attribute this codebase calls actually
# exists in that specific build/platform. After installing, ALWAYS run:
#   python3 tools/check_hardware_deps.py
# before going to the robot, not during a live session. It checks the real
# attributes directly (hasattr), not just version strings.

numpy>=1.24
scipy>=1.11
pyyaml>=6.0
mujoco>=2.3.3

# CONFIRMED BAD: 1.6.1 lacks RTDEControlInterface.directTorque, despite
# satisfying this project's old ">=1.6" documentation. The exact minimum
# version that actually has directTorque() is NOT yet confirmed (as of
# 2026-07-30) -- pin to the latest available (1.6.3 as of this writing) and
# VERIFY with tools/check_hardware_deps.py rather than trusting this floor
# alone. If you confirm a specific working minimum, update this comment.
ur_rtde>=1.6.3

# CONFIRMED GOOD on the simulation host (mujoco_ur5e conda env, pinocchio
# 4.0.0 via pip, buildModelFromMJCF present) -- but this was NOT reliably
# true on a plain-venv real-hardware host at >=3.1, so the floor alone is
# not trustworthy either. VERIFY with tools/check_hardware_deps.py.
pin>=4.0
